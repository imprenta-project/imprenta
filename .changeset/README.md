# Changesets

A change that anybody outside this repository can notice needs a changeset:

```bash
pnpm changeset
```

It asks which packages moved and how far, then writes a markdown file here.
That file is the release note — write it for somebody reading the changelog on
npm, not for somebody reading the diff.

## What is specific to this repository

**The five packages share one version.** `@imprentajs/pdf`, `@imprentajs/xlsx`,
`@imprentajs/react`, `@imprentajs/fonts` and `@imprentajs/cli` are a `fixed` group in
`config.json`, so a changeset for any of them bumps all five. That is on
purpose: `@imprentajs/cli` is a compiled artefact of the napi crates, and a CLI
that shipped against a `@imprentajs/pdf` it was never tested with is the failure
this whole repository is careful about. One version means one combination, and
the combination is the thing that was tested.

The cost is that `@imprentajs/react` gets a new version when nothing in it
changed. That is the cheaper of the two mistakes.

**The platform packages are not here.** `@imprentajs/pdf-darwin-arm64` and its
nine siblings are generated by `napi prepublish` from the `napi.targets` in each
package, and they take the version of the package they belong to. Changesets
never sees them and must not: there is nothing to write a release note about in
a file that is one compiled `.node`.

**We are in pre-release.** `pre.json` says `alpha`, so `changeset version`
produces `0.1.0-alpha.N` and the release publishes under the `alpha` dist-tag.
Not a custom one: changesets refuses `--tag` in pre mode outright. Leaving
pre-release is one command and a deliberate act:

```bash
pnpm exec changeset pre exit
```

The full documentation is
[in the changesets repository](https://github.com/changesets/changesets).
